# PORTFOLIO_SELLING_SYSTEM_MASTER_PLAN.md

# Purpose

Rebuild the portfolio into a **client-converting sales asset**, not merely a visually impressive developer portfolio.

The objective is to make a potential client quickly understand:

1. Who Miko is.
2. What problems he solves.
3. What systems he builds.
4. Why he is technically credible.
5. What business value he provides.
6. What the visitor should do next.

Core positioning:

> **I build production software systems that automate complex business workflows.**

Do not turn the portfolio into a generic freelancer website.

---

# 6. Animation Rules

Animation is valuable only when it explains something.

## Good animation

- Data moving through a pipeline
- Workflow stages activating
- APIs exchanging information
- AI retrieval showing relevant context
- Resources changing states
- Geographic layers appearing
- Before/after transformation

## Bad animation

- Random floating particles
- Constant gradient movement
- Excessive parallax
- Decorative objects flying around
- Animation on every card
- Motion that delays content

Rule:

> **Every major animation must communicate a concept.**

Respect `prefers-reduced-motion`.

# 25. Technical Credibility Pattern

For every major project:

```text
PROBLEM
   ↓
CONSTRAINT
   ↓
ENGINEERING DECISION
   ↓
IMPLEMENTATION
   ↓
RESULT / CAPABILITY
```

Example:

> **Problem:** External APIs have rate limits.

> **Constraint:** Large processing jobs cannot run without throttling.

> **Decision:** Chunk requests and rate-limit processing.

> **Implementation:** Controlled API calls through the workflow.

> **Result:** The pipeline can process data without treating external APIs as unlimited resources.

Only use examples supported by the actual project.
